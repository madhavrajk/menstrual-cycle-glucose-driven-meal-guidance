# Decisions

Newest first. "Provisional" means the code uses it now, but the group hasn't confirmed it.

| Date | Decision | Status | Why / notes |
|---|---|---|---|
| Oct 15 | **Interval scope:** Interval 1 (2022) is primary for all models. | Settled by data | Interval 2 has no CGM, almost no diary entries, and no flow data (Ava's coverage report). Interval 2 is used only for wearable-only sensitivity checks, if at all. |
| Oct 15 | **Glucose units:** convert all readings to mg/dL. Values ≤ 30 are treated as mmol/L (× 18.016). | Settled | The README says mmol/L, but 2 of 42 participants have some mg/dL readings (4.1% of rows; 5 days mix both). Dexcom's ranges (2.2–22.2 mmol/L, 40–400 mg/dL) don't overlap, and no values fall between 22.3 and 39.9. **Ava: the Step 1 replication must use converted values, so use `cgm_daily.csv`, not raw `glucose.csv`.** |
| Oct 15 | **CGM day validity:** ≥ 70% of 288 readings (≥ 202). | Settled | **Real data:** 2,856 of 3,108 Interval 1 days (92%) pass; median 78 valid days per participant. One participant has 0 valid days, so the glucose target covers 41 people. The consensus statements give a *period-level* rule: about 14 days with ≥ 70% of possible readings (Danne et al. 2017; Battelino et al. 2019, *Diabetes Care* 42(8):1593, the TIR consensus). Neither defines a per-day rule, so we apply the same 70% to each day, because our unit is the day. If `make cgm` shows too few valid days, drop to 60% and report N for both. Add Battelino 2019 to the references. |
| Oct 15 | **Glucose target:** high-variability day = CV in the participant's own top third of valid days. Need ≥ 10 valid days. | Per proposal | The threshold uses all of a person's days. Fine for a label, never a feature. |
| Oct 15 | **Time in range:** report both 70–180 and 70–140 mg/dL. | Settled | Healthy participants sit near 100% in 70–180. |
| Oct 15 | **Symptom target:** next-day score ≥ 3 ("Moderate") on the 0–5 diary scale. | Provisional → **decide at review** | **Real prevalence at ≥ 3:** fatigue 55%, cravings 35%, bloating 31%, cramps 16%. "High" fatigue on half of all days isn't a meaningful flag. Options: ≥ 4 for fatigue only, or a person-relative threshold (above the person's own past mean), which also fits the finding below. |
| Oct 15 | **Baselines on real data** (`results/baselines_real.csv`). | Result | Symptoms are trait-like: the per-person base rate (AUROC 0.81–0.86 for fatigue, bloating, cravings) matches or beats persistence. **Step 2 models must beat about 0.85 on symptoms, not 0.5.** For next-day high-CV glucose, persistence is only 0.565 [0.545, 0.588] and the base rate is uninformative by construction, so this target is harder and any watch-based signal above 0.57 counts. |
| Oct 15 | **Leakage rule:** features and baselines at day t use only days ≤ t, and labels known by t (≤ t−1 for next-day labels). Splits are leave-one-subject-out. | Settled | Covered by `tests/test_leakage.py`. |
| Oct 15 | **Repo:** one private repo; Ava's `mira-cycle-analysis` imported (Ava's authorship kept) so it can be deleted. | Done | Public release review in Week 10. |
| Oct 8 → open | **Primary phase scheme:** LH-anchored (ours) vs. shipped Mira labels. | Open | Suggested: LH-anchored primary, Mira as cross-check. LH labels cover only 31% of days today (1,746 / 5,659), so coverage must improve first. |
| Oct 8 → open | **LLM setup for Step 3:** local model vs. zero-retention API vs. sending only derived state. | Open | Sneha's options page, then instructor confirmation before any real participant day reaches a hosted model. |
